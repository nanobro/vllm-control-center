# vLLM Control Center UX/UI Overhaul Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Turn the vLLM Control Center from a developer console into a calm, trustworthy control surface: one obvious model-running flow, honest status language, live feedback on every state change, and a visual identity with real character instead of the generic Inter-on-gray default.

**Architecture:** Keep the existing React 19 + Vite + TanStack Query stack and the FastAPI backend contract unchanged. The overhaul is frontend-only: (1) collapse the 22-page sprawl into 4 primary surfaces, (2) replace the 1,984-line `ServerPage.tsx` with a state-machine-driven "Run" page, (3) introduce a design system (tokens, type pairing, components) in `style.css` + small shared components, (4) wire live feedback (polling cadence, progress phases, toasts, empty states). Backend changes are limited to one optional read-only endpoint for load-phase progress.

**Tech Stack:** React 19, TypeScript, Vite 8, TanStack Query 5, lucide-react, plain CSS (design tokens via `:root` custom properties). No new runtime dependencies.

**Branch discipline:** All work lands on `feature/v0.79-recipe-load-eject`. PR #1 stays Draft. Never push `main`, never force-push. Verify `npm run check` (typecheck + build) and the controller suite before every push.

## Design Direction

Open with the thing this product IS: a machine status board. The Run page leads with a large live status readout (model name in a display face, state in a colored signal lamp, elapsed timer ticking), not a form.

- **Type pairing:** Display face for headings and big numbers - "Space Grotesk" (or "Sora"); body face - "IBM Plex Sans"; monospace for endpoints, logs, model IDs - "IBM Plex Mono". Loaded via `@fontsource` packages or a single `<link>` to a self-hosted subset; no external CDN dependency at runtime on the DGX (fonts must work offline - bundle them).
- **Palette:** Deep slate-green control room, not indigo. Base `#0e1512` sidebar, surface `#f4f6f3`, ink `#16211b`, signal green `#2fbf71` (running), amber `#e8a33d` (attention/loading), red `#e5484d` (crashed/blocked), cool gray for idle. One accent used sparingly: green.
- **Motion:** Status lamp pulses when `starting`; progress bar animates; cards lift 2px on hover with 150ms ease; page content fades/slides 8px in on nav (CSS keyframes, respect `prefers-reduced-motion`); toasts slide in from bottom-right.
- **Texture:** Sidebar gets a faint grid/dot pattern (CSS radial-gradient dots), main area stays calm. No glassmorphism, no aurora blobs, no gradient headline text.

## Task 2: Signal lamp + status pill component (~15 min)

**Objective:** One honest, animated status vocabulary used everywhere.

**Files:**
- Create: `frontend/src/components/StatusLamp.tsx`

**Step 1: Component**

```tsx
const STATE_META: Record<string, { color: string; label: string; pulse?: boolean }> = {
  running:  { color: 'var(--ok)',     label: 'Running' },
  starting: { color: 'var(--warn)',   label: 'Starting', pulse: true },
  stopping: { color: 'var(--warn)',   label: 'Stopping', pulse: true },
  crashed:  { color: 'var(--danger)', label: 'Crashed' },
  blocked:  { color: 'var(--danger)', label: 'Blocked' },
  stopped:  { color: 'var(--idle)',   label: 'Stopped' },
};

export function StatusLamp({ state, detail }: { state: string; detail?: string }) {
  const meta = STATE_META[state] ?? STATE_META.stopped;
  return (
    <span className="status-lamp" style={{ ['--lamp' as string]: meta.color }}>
      <i className={meta.pulse ? 'dot pulse' : 'dot'} />
      <strong>{meta.label}</strong>
      {detail && <span className="lamp-detail">{detail}</span>}
    </span>
  );
}
```

**Step 1: Timer hook**

```tsx
function useElapsed(startIso: string | null) {
  const [now, setNow] = useState(Date.now());
  useEffect(() => {
    if (!startIso) return;
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(id);
  }, [startIso]);
  if (!startIso) return null;
  const s = Math.max(0, Math.floor((now - new Date(startIso).getTime()) / 1000));
  return `${Math.floor(s / 60)}:${String(s % 60).padStart(2, '0')}`;
}
```

## Risks, Tradeoffs, Open Questions

- **Font bundling size:** three fontsource families add ~300KB to the bundle. Acceptable for a LAN/Tailscale tool; revisit with subsetting if it bothers anyone.
- **Page deletion is destructive:** Task 5 deletes 10 files. Mitigated by git history + the fold map; verify each page's unique data is preserved before `git rm`.
- **Log-derived phases (Task 3) are heuristic:** if vLLM log format shifts, phases stall. The optional Task 8 endpoint is the durable fix; ship Task 3 first because it needs zero backend change.
- **Open question - ServerPage fate:** `ServerPage.tsx` (1,984 lines) stays as the Advanced-mode escape hatch for now. A follow-up plan should split it into config/metrics/logs subcomponents or delete it once the Run page covers 95% of needs.
- **Open question - Remote pages:** `RemoteControllersPage` (662 lines) was not reviewed in depth. If Remote stays primary, it deserves its own UX pass (phase 2).
